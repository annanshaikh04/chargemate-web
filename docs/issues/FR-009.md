# [FR-009] Legal placeholder and accessibility baseline

## Labels
`MUS`, `enhancement`, `legal`, `a11y`

## User Story
As a visitor, I want legal placeholders and sensible heading/landmark structure, so that the prototype is presentable and accessible.

## Proposed Solution

### Overview
Add `src/app/legal/page.tsx` mirroring `docs/mockups/legal.html`. Audit all pages for: single `h1` where appropriate, logical heading order, `main` landmark, nav labels, focus styles (Tailwind `focus:ring`).

### Implementation Flow
1. Legal page with Privacy, Terms, Crowdfunding disclaimer stubs.
2. Pass through layout + each page for landmarks and heading order fixes.
3. Ensure interactive elements are keyboard reachable.

### Technical Approach

```tsx
export const metadata = { title: 'Legal | Cordline' };
export default function LegalPage() { ... }
```

### Key Considerations
- Legal text is explicitly placeholder; not for production.
- Do not claim compliance with WCAG without audit; “baseline” means obvious fixes only.

## Acceptance Criteria

- [x] `/legal` exists with three labeled sections (Privacy, Terms, Crowdfunding disclaimer)
- [x] Each public page has one main content landmark (`main`)
- [x] Heading levels do not skip inappropriately on standard flows
- [x] Primary navigation has accessible name (`aria-label`)
- [x] Matches `docs/mockups/legal.html` structure
